# 部署与配置

使用 Docker Compose 时，默认将宿主机8080映射到容器8000，并将当前目录下的data挂载到/data。首次访问创建一个账号；同一实例内所有资产属于该账号。

## 环境变量

| 变量 | 默认 | 用途 |
| --- | --- | --- |
| DATA_DIR | backend/data（容器为/data） | SQLite、图片、附件、临时导入及账号目录 |
| TZ | Compose中为Asia/Shanghai | 容器时区 |
| SEED_DEMO | 0 | 1时仅向空库写入虚构演示资料 |
| GUEST_LOGIN | 0 | 1时允许guest免密码，不得用于私人实例 |
| SESSION_COOKIE | keeps_session | 同域多实例时分别设置不同Cookie名 |
| KEEPS_API_URL | http://127.0.0.1:8000 | 仅Vite开发代理的后端地址 |

运行多个实例时，数据卷、Cookie名和端口都应独立。不要把一个实例的数据库或账号目录覆盖到另一个实例。

## 反向代理

公网部署应配置HTTPS。保留原始Host（含非默认端口），传递X-Forwarded-Proto，并仅信任实际反向代理的转发头。应用会校验写请求的Origin与Host及X-Keeps-Request标记；不要通过关闭校验解决代理问题。

上传备份的代理限制应允许512MB请求；恢复大包时按实际网络情况延长代理超时。数据目录应仅允许运行应用的账号访问。应用当前为个人自托管产品，首次账号初始化前先限制外部访问。

## 升级与回退

升级前保留数据目录的一致备份，保存当前应用版本。更新代码并重新构建镜像，再启动容器。先验证登录、资产、图片和附件读取；不要用演示数据覆盖原卷。回退代码不能自动撤销数据库结构变化，恢复数据库前应先停止写入并保留当前数据。

Docker构建结果仍需在支持Docker的环境验证。本次公开包准备环境未安装Docker，静态检查与本地构建通过不等于镜像构建已通过。
